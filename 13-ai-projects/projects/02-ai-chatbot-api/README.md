# Project 02 — AI Chatbot API

> Stage: 13 · Difficulty: ⭐⭐⭐

## Assignment

Build a **chat API** — the backend for a chatbot. It maintains conversation history (persisted!), streams responses to the client, and supports multiple conversations per user. No frontend needed (or a tiny HTML page to demo streaming).

## Endpoints

```
POST   /api/conversations        → create a conversation → { id }
GET    /api/conversations        → list my conversations (title = first user message)
GET    /api/conversations/:id    → full message history
POST   /api/conversations/:id/messages
        body: { content }        → streams back the AI reply (SSE)
DELETE /api/conversations/:id    → delete
GET    /api/conversations/:id/rename   → set a custom title
```

## Streaming — the important part

`POST .../messages` responds with **SSE (Server-Sent Events)**:

```
data: {"type":"token","text":"Hello"}
data: {"type":"token","text":" world"}
data: {"type":"done","messageId":"..."}
```

The response accumulates the AI's reply, **saves the full message to history**, and streams tokens as they arrive. Use Express + `res.write` or the OpenAI SDK's stream directly piped through.

## Persistence

Messages persisted (SQLite is fine):

```ts
interface Conversation { id, userId, title, createdAt }
interface Message { id, conversationId, role: "user" | "assistant", content, createdAt }
```

System prompt stored per conversation too (persona for the bot).

## Requirements / acceptance criteria

- [ ] History survives restart; the bot remembers earlier messages in a conversation (context window built from stored history)
- [ ] Streaming works from a browser (SSE via `fetch` + `ReadableStream` reading, or `EventSource`)
- [ ] Messages are saved atomically: user message saved on receipt, assistant message saved when the stream completes (handle mid-stream failures)
- [ ] Simple auth (your Stage 08 JWT pattern) — conversations are per-user
- [ ] Context trimming: when history exceeds a token budget, trim oldest messages (log what you did)
- [ ] Errors: LLM failure → SSE `data: {"type":"error",...}` then close; client handles gracefully
- [ ] `npx tsc --noEmit` passes; `.env` gitignored

## Hints

- SSE headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, keep the connection open.
- Build a `chatService.generateReply(conversationId, content, onToken)` that owns LLM + persistence — keep it testable (no res/res in the service).
- `for await (const chunk of stream)` gives you deltas; forward `chunk.choices[0]?.delta?.content`.
- Save the assistant message ONLY after the stream finishes (or save incrementally with a "pending" state).
- Context trimming: count tokens with the SDK tokenizer; keep last N tokens + always keep the system prompt.

## Stretch goals

- Add a `POST /api/conversations/:id/system` to change the bot persona mid-conversation.
- Add conversation titles auto-generated by a cheap model call.
- Rate-limit the streaming endpoint (tokens are money).
- Add a plain-HTML demo page with a chat box that streams.

## How to run

```bash
npm init -y
npm install express openai zod better-sqlite3 jsonwebtoken bcryptjs dotenv
npm install -D typescript tsx @types/node @types/express
node src/index.ts
# POST a message, observe the SSE stream in the terminal / a browser page
```
